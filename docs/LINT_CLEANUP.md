# 린트 정리와 동작 검증

확인일: 2026-10-20. 공개 저장소의 의존성 보안 업데이트 이후 남아 있던 ESLint 오류 43건·경고 21건을 모두 해결했다. 기존 운영 서비스와 비공개 저장소는 변경하지 않았다. 의존성과 잠금 파일, DB 마이그레이션, API 계약은 이번 변경에서 유지했다.

## 변경 내용

- React 렌더 중 DOM·지도 SDK ref를 읽던 코드를 DOM 부착 callback이나 SDK 이벤트로 옮겼다.
- 계산 가능한 값은 렌더에서 유도하고, 사용자 조작에 따른 초기화는 이벤트에서 처리한다. 비동기 질의는 취소·학교/입력값 구분을 유지해 이전 응답이 새 화면에 나타나지 않도록 했다.
- 지도 초기 선택은 URL 변경을 반영하되, 관심목록·마이페이지 등 패널 query 변경은 기존 지도 인스턴스를 유지한다. 지역 변경은 필터와 선택을 함께 초기화한다.
- Portal·로그인 창의 브라우저 준비 상태와 밝기 상태는 `useSyncExternalStore`로 구독한다. 저장소 쓰기가 차단돼도 화면에 적용한 밝기의 선택 표시가 유지된다.
- 검색 결과 키보드 선택, 닉네임 확인의 기존 350ms 지연, 학교 시트의 끌어 조절, 설문 펼침 위치 계산을 유지했다. 사용하지 않는 값과 누락된 Hook 의존성도 정리했다.

린트 규칙·가드 기준을 완화하거나 앱 소스를 검사에서 제외하지 않았다. Supabase CLI 실행 중 생기는 `supabase/.temp/**`, `supabase/.branches/**`만 기존 Git 제외 설정과 같이 ESLint에서도 제외했다. 생성된 SDK 번들이 앱 소스로 검사되는 것을 막기 위한 설정이다.

`npm run lint`는 `eslint --max-warnings=0`으로 경고도 실패로 처리한다. `npm run checks`에 전체 린트와 실제 밝기 helper를 사용하는 회귀 검사 8개를 추가했다. 새 패키지는 추가하지 않았다.

## 확인 결과

Node.js 24.19.0, npm 11.17.0에서 공개본을 별도 clone해 검증했다. 기존 서비스의 환경변수나 외부 API 키 대신 별도 로컬 Supabase에 마이그레이션 55개와 합성 seed를 적용했다.

| 검사 | 결과 |
|---|---|
| 새 `npm ci --no-fund` | 성공, peer 오류 없음 |
| 전체·실행 의존성 `npm audit` | 각각 취약점 0건 |
| `npm run checks` | 전체 린트 오류·경고 0건, 계산·통근 72개, glob 29개, 밝기 8개, 가드 4종 통과 |
| `npm run selftest:deployment` | 5개 통과 |
| 원문 판독·학교 매칭 | `npm run read`, `npm run match:all` 통과 |
| `npm run build` | 기본 Turbopack·TypeScript 검사 성공, 정적 페이지 6,461개 생성 |
| 로컬 HTTP 회귀 검사 | 개발·프로덕션 실행에서 각각 24개 통과 |

위 명령은 단계별로 실행했다. `verify`의 판독·매칭·checks 통과 후 빌드에서 발견한 null 검사 오류를 수정했고, 최종 소스에서 `checks`와 프로덕션 빌드를 다시 통과했다. HTTP 검사는 입력 오류, 통근 seed 캐시, 캐시 없음, 미인증 새 경로 차단, 주소 키 미설정 응답, 공개 집계·학교 목록을 확인했다.

실제 브라우저에서는 프로덕션 실행의 경기·인천 계산값 변경, 밝기 선택, 화면 이동 시 메뉴 닫기, 학교 상세, 로그인 취소 안내·Esc 닫기, 비로그인 관리자 접근 차단을 확인했다.

별도 임시 화면에서는 실제 컴포넌트와 합성 지도 SDK·로컬 DB를 사용해 다음을 확인했다. 이 화면과 합성 키는 공개 소스와 최종 빌드에서 제거했다.

- URL의 지역·학교 선택 반영, 패널 전환 시 지도 인스턴스 유지, 지역 변경 시 선택 초기화
- 학교 변경 시 별점·통근 경로 초기화, 캐시 경로 선택·방향 전환
- 검색 키보드 선택, 설문 기간 펼침, 학교 시트의 데스크톱 포인터 끌기와 높이 유지
- 로그인 Portal 열기·닫기, 닉네임 형식 검사·비동기 실패 표시·공백 수정 시 재검사

## 남은 확인 범위

실제 NAVER 지도 인증·타일·신규 길찾기, Kakao 주소 검색, Google OAuth와 로그인 후 닉네임·관심학교 저장·관리자 작업 성공은 본인의 키와 계정으로 확인해야 한다. 합성 SDK 검사는 외부 제공자 연동이나 실제 모바일 기기 검증을 대신하지 않는다. 밝기 저장소 차단 검사는 브라우저 API fixture로 실행했다.

새 로컬 DB에서 기존 조회수 기록 권한 문제도 확인했다. `school_views`에 쓰는 서버 역할의 테이블 권한이 빠져 `/api/view`가 `{ok:false}`를 반환한다. 이번 린트 변경 전부터 존재하는 API·마이그레이션이며 수정하지 않았다. 조회수 기록 성공은 이번 검증의 통과 범위에 포함하지 않는다. 해결 시 서버 역할에 필요한 권한만 검토해야 하며, 원시 조회 기록을 익명 사용자에게 공개하는 방식은 사용하지 않는다.

기존 ESLint 9 유지보수 종료 안내와 Next.js `middleware` 파일 관례 변경 경고는 [의존성 검증 기록](DEPENDENCY_SECURITY.md)에 남아 있다.
